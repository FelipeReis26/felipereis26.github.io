At work

I'm a Service Desk Analyst III at a global sports betting and gaming company. The desk supports people in the US, UK and Ireland. These tools are internal. There are no screenshots or links here, only what they do and the numbers.

New hire access

~23access tickets from one new hire request.

Google Apps Script, JavaScript, Jira APIs, built with Claude

Every new starter used to mean raising around 23 access tickets by hand. The set changed every time, depending on the role. I went through about 1,600 old tickets to work out what each role needs and who signs it off. Those findings became the rules.

It runs in test mode by default. Before every run it checks Jira is set up the way it expects. It asks twice before it writes anything for real. A journal means a run that stops halfway never makes duplicates. The subject matter experts signed it off, and it's been in production since July 2026. Since October it runs from the desk's New hire hub.

Vendor status dashboard

81vendor status pages watched, with Slack alerts when one goes down.

Google Apps Script and Slack, now being rewritten in Node and Docker

We paid for a service that watched vendor status pages. Nobody really knew if it was any good. I built my own and ran the two side by side for a few weeks, comparing them every day. Mine caught everything the paid one caught. It also caught outages the paid one missed. One of those was an 8 hour outage at a Tier 1 vendor. The subscription costs around $4,000 a year and is set to be cancelled.

I'm now rewriting it as its own service in Docker, to run on AWS. Every parser is checked against the old version on the same inputs. That check found two problems in the old one. AWS's status feed is UTF-16 and was being read as UTF-8, which meant AWS was never really watched. DocuSign had also moved its status page.

The desk's automation hub

Morning triage, ticket QA and the team's numbers in one app.

Google Apps Script web app, JavaScript, Jira and Slack APIs, GitHub

The desk's day used to live in a dozen places. The hub is one web app for the triage queue, ticket QA and live dashboards of what the team has resolved. Anything that writes to Jira shows you the change and asks first.

It's had dozens of versioned releases. The code is on GitHub behind protected branches and a build and verification pipeline. A few techs used it on real working days before it went wider. I presented it to the team at a company offsite. The desk runs a stable build on purpose. New things like an AI lab and an on call page get tried in a Docker sandbox first.

Knowledge base cleanup

~700pages, over 100 of them reviewed by hand so far.

Confluence, KCS, Jira automation. Co-leading, still going

The desk's knowledge base had no owners and no review cycle. A colleague and I are cleaning it up the KCS way. We've been through all of it, and I've reviewed over 100 pages myself. We wrote a page template that names an owner, and proposed a 90 day review cycle. I've also written 19 guides and runbooks.

Scheduled checks

~14checks that run whether anyone remembers them or not.

Claude, scheduled agents, Jira, Slack and Confluence APIs

The small checks that keep a desk healthy only happen when someone remembers. I set them up to run on their own. One checks the weekly P1 handover and reminds the right people. One catches customer replies on tickets that are already resolved. One finds resolved tickets with no priority. One matches new tickets against 14,498 resolved ones to show how we handled the same thing before.

Two of them are shared with the wider desk through a plugin catalogue we set up with Platform Engineering. In November I folded ten of them into one morning brief. Slack now only gets the urgent ones.

Tessera

Web app and iPhone app · React, TypeScript, Supabase, Vercel, Capacitor · Open it

My friends and I play the same daily puzzles: Wordle, Connections, Queens and more. I built one place for all of them. Each game is a tile. You tap it, play, and come back. If you were gone long enough, the tile ticks itself off. There's an undo. Your group shares one board and can see who's done what today. Every game has its own streak and calendar.

The tick was the hard part. It only counts a real departure, when the page actually goes hidden. A focus flicker can't fake it. If iOS kills the page while you play, it still catches you coming back. Reminders are web push, and the rules for them are written and tested in SQL. Every table has row level security, covered by database tests.

Final Whistle

Football match predictor · Python, JavaScript, GitHub Actions

It predicts home, draw and away chances for the top leagues in ten European countries, plus the Champions League and Europa League. The model uses Elo ratings, recent form and a goals model. The bookmakers' prices sit next to it.

I held it to being honest. Every setting was picked on a validation set. On 4,194 matches it never saw, it gets close to the bookmakers but doesn't beat them. The write up says that plainly. It also says which betting strategies lose money. A GitHub Actions job logs a prediction for every fixture four times a day. Each prediction is its own commit, which proves it was made before kickoff. The phone page is password protected, so there's no link.

GILD

Budget app · React, Capacitor, on my iPhone · Live app · Code

My budget app. On payday it splits the pay across bills, savings and spending limits. The home screen shows what's safe to spend today. Bank statements import straight in. Repeat charges get flagged as subscriptions. The scan screen turns a payment screenshot into a transaction I check before saving.

Nothing leaves the phone. There's no server, no account and no bank connection. iOS can clear a web view's storage on its own. The iPhone app keeps a copy in its own files and loads it back before it starts.

Tripsy

Trip planner · HTML, CSS, JavaScript, Vercel functions, an iPhone app

A trip planner my partner and I actually use. Each trip is its own page. The home page works out our leave days and moves trips from upcoming to past by itself. Adding a trip goes through a form and a small serverless function. The function commits the new page straight to GitHub, and the site redeploys.

The GitHub token can only touch that one repo and never reaches the browser. We each get a packing list per trip. Two phones saving at once can't overwrite each other. The iPhone app has every trip offline. GILD reads our trip costs through a read only feed. The site holds our real travel dates, so it's behind a login and there's no link.
